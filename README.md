# LZC Complexity Library

This repository contains the C implementation of the Lempel–Ziv Complexity (LZC) parser used in the Snooz Toolbox.

The LZC parser is implemented in C because this part of the calculation can be computationally intensive. The compiled C library is then called from Python using `ctypes`.

This repository includes GitHub Actions workflows to compile the C code for the operating systems supported by Snooz and to check that the generated libraries work consistently across platforms.

## Supported Platforms

The C code is compiled for the following platforms:

| Platform | Architecture | Generated file |
|---|---|---|
| Windows | x64 | `calculate_complexity_64.dll` |
| Linux | x64 | `calculate_complexity_64.so` |
| macOS | Intel x86_64 | `calculate_complexity_x86_64.dylib` |
| macOS | Apple Silicon ARM64 | `calculate_complexity_arm64.dylib` |

## C Implementation

The Lempel–Ziv parser is implemented in `calculate_complexity.c`.

The main functions used by the Python code are:

- `complexity()` for one-dimensional binary sequences. This is used for the univariate and concat modes.
- `complexity_joint()` for multichannel binary data used in joint mode.

For joint LZC, the C code automatically divides the channels into groups of a maximum of 50 channels when needed.

## Building the Libraries

The libraries are automatically compiled using GitHub Actions. The build workflow is defined in:

```text
.github/workflows/build.yml
```

The same C code is compiled on four different GitHub runners:

```text
calculate_complexity.c
        │
        ├── Windows x64
        │      └── calculate_complexity_64.dll
        │
        ├── Linux x64
        │      └── calculate_complexity_64.so
        │
        ├── macOS Intel
        │      └── calculate_complexity_x86_64.dylib
        │
        └── macOS ARM64
               └── calculate_complexity_arm64.dylib
```

The generated files are uploaded as GitHub Actions artifacts and can be downloaded from the corresponding workflow run.

The build workflow runs automatically when `calculate_complexity.c` or the build workflow itself is modified. It can also be started manually from GitHub Actions.

## Testing

A separate workflow is used to check that the compiled libraries work correctly on each operating system.

The workflow is defined in:

```text
.github/workflows/test.yml
```

and the Python test code is located in:

```text
tests/test_complexity.py
```

The main goal of this test is to make sure that the `.dll`, `.so`, and `.dylib` files can all be loaded and called from Python using `ctypes`, and that they return the same results for the same inputs.

### How the Test Works

The Windows version is used as the reference.

First, the workflow compiles the Windows DLL and runs a few fixed binary sequences and a multichannel binary matrix through the C functions.

The results are saved in `reference_results.json`.

```text
Windows DLL
     │
     ├── complexity(test sequence 1)
     ├── complexity(test sequence 2)
     └── complexity_joint(test matrix)
     │
     ↓
reference_results.json
```

The Linux and macOS jobs then run the same inputs using their corresponding compiled libraries and compare their results with the Windows results.

```text
                    Windows
                  reference results
                        │
          ┌─────────────┼─────────────┐
          ↓             ↓             ↓
       Linux         macOS Intel    macOS ARM64
        .so            .dylib         .dylib
          │             │             │
          └─────────────┼─────────────┘
                        ↓
                Compare results
```

If the results are the same, the test passes. If any result is different from the Windows reference, the corresponding test job fails.

The DLL generated by GitHub Actions was also manually compared with a previously compiled and tested Windows DLL using the same inputs, and both DLLs returned the same results.

These tests are mainly intended to check that the compiled libraries can be used through `ctypes` on all supported platforms and that the C implementation behaves consistently across operating systems.

## Compilation Commands

The following commands are used by the build workflow.

### Windows x64

```bash
gcc -O2 -shared -o calculate_complexity_64.dll calculate_complexity.c
```

### Linux x64

```bash
gcc -O2 -fPIC -shared -o calculate_complexity_64.so calculate_complexity.c
```

### macOS Intel x86_64

```bash
clang -O2 -dynamiclib -o calculate_complexity_x86_64.dylib calculate_complexity.c
```

### macOS Apple Silicon ARM64

```bash
clang -O2 -dynamiclib -o calculate_complexity_arm64.dylib calculate_complexity.c
```

## Use in Snooz

These compiled libraries are used by the Lempel–Ziv Complexity implementation in Snooz. Python communicates with the C library using `ctypes`.

The complexity tool supports three modes:

- **Univariate:** LZC is calculated separately for each EEG channel.
- **Concat:** the binarized channels are concatenated into one sequence before calculating LZC.
- **Joint:** the binary states of multiple channels are analyzed together.

The EEG preprocessing, binarization, surrogate generation, and normalization are handled in Python, while the Lempel–Ziv parsing itself is performed by the C code.
